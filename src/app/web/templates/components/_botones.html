{# Componente: Botones — PaqueteX Design System Variante aprobada: "Vívida" (rounded-lg, shadow-sm→hover:shadow-md, anillo de foco). Paleta y tokens documentados en docs/design-system/tokens.md — esa es la fuente de verdad, este archivo solo la implementa. Colores corregidos el 2026-07-29 a los valores EXACTOS de `.btn-primary`/`.btn-success`/ `.btn-warning`/`.btn-danger` de producción (`paqueteex.papyrus.com.co`, `CODE/src/static/css/components/buttons.css`). Cambio más notable: `warning` es NARANJA (`orange-600`), no ámbar — con naranja el texto blanco sí pasa AA, así que ya no hace falta el texto oscuro que usaba la versión anterior de este macro. Uso: {% from 'components/_botones.html' import boton %} {{ boton('Guardar') }} {{ boton('Confirmar entrega', variant='success', size='lg') }} {{ boton('Cancelar paquete', variant='danger', extra_attrs='hx-post="/paquetes/1/cancelar" hx-confirm="¿Confirmas?"') }} {{ boton('Enviando…', loading=True) }} {{ boton('No disponible', disabled=True) }} {{ boton('Anunciar', type='submit', full_width=True) }} No se generan plantillas separadas por tamaño/dispositivo: `size` es un parámetro explícito (sm/base/lg), no un breakpoint — el mismo macro sirve para cualquier viewport. Tamaño `base` ajustado el 2026-07-31 para igualar el alto real de producción (medido en vivo: 50px, texto 16px, `padding: 12px 32px`). `sm`/`lg` subieron en la misma proporción para que la escala completa siga teniendo sentido (antes `lg` quedaba más chico que el nuevo `base`). `full_width=True` agrega `w-full justify-center` — pensado para el CTA de cierre de un formulario de flujo (ver `_formularios.html`), no cambia nada para quien no lo pasa. `icono` es OPCIONAL (`none` por defecto, corrección en vivo 2026-08-01) — recibe un valor de `iconos_nav` (global de Jinja), siempre en su wrapper "outline" (viewBox 24x24, stroke), igual que `input_texto`. Se oculta si `loading=True` (el spinner tiene prioridad, nunca los dos a la vez). `name`+`value` (ticket 06, `.scratch/announce-rapido`): para un `
` con más de un botón `type='submit'` que deban distinguirse en el servidor (ej. Anunciar vs. Recibir, mismo form) — el navegador solo manda el `value` del botón que se haya pulsado. HTMX/Alpine NO se asumen por defecto (regla: solo se integran si la funcionalidad lo exige).
